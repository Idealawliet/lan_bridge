# LAN Bridge · 跨屏协作

用同一副键盘和鼠标，在局域网内多台 Windows / macOS 电脑之间切换。Flutter（Dart）负责桌面界面、配对和加密通信；Windows C++ 与 macOS Swift 插件负责系统级输入捕获、注入和紧急恢复。

这是 v0.9.1 预览版工程，包含两端源码、测试与双平台构建/发布工作流。**构建配置不等于已发布安装包**：Windows 和 macOS 客户端需要在对应系统构建，正式发行还需要平台签名、公证和双机实测。

v0.4.1 修复多机切换后的旧输入事件、紧急恢复后的队列残留、剪贴板暂停与失败重试，以及退出控制组的输入通道清理。详见 [缺陷修复记录](docs/bugfixes-0.4.1.md)。

## 已实现的范围

- 一台服务端提供键鼠，最多 16 台客户端保持独立加密连接；各电脑运行同一个应用。另保留原双机手动连接模式。
- 自动发现同一 IPv4 局域网 / Wi-Fi 中已启动的服务端与客户端，显示名称、系统、地址与忙碌状态。发现本身不授予控制权限。
- 两块主屏幕可拖动到上、下、左、右并错位排列；指针越过指定边缘后，键盘输入跟随指针切换，向反方向移动可回到本机。
- 键盘物理按键、鼠标移动、左右/中/侧键、滚轮；不同屏幕尺寸按相接边缘的比例衔接。
- 发现或输入客户端 IP，使用 6 位数字 PIN 码配对，TCP 端口 `24872`；每次等待生成新 PIN，不保存 PIN 或记录按键内容。
- 双向挑战认证、会话密钥派生、AES-256-GCM 加密与有序帧验证；每台客户端仅接纳一台已配对控制端；服务端可管理多个客户端会话。
- 连接存活检查、原生心跳保护与紧急返回快捷键，断开时释放模拟按键和鼠标按钮。
- 服务端固定为键鼠主机，客户端固定为被控电脑；不再独立选择网络角色。
- Windows / macOS 登录后自启，自动记住键鼠角色、网络角色和屏幕布局。

- 双向文本、图片和原始文件剪贴板同步，可暂停；文本/图片上限 8 MiB，文件沿用文件传输上限。
- 文件与文件夹双向传输，保留目录结构及空文件夹，分块确认与 SHA-256 校验。
- 已接入 Windows OLE 与 macOS NSDraggingSession 跨屏文件拖放；**仍需两端原生构建及 Explorer / Finder 实机验收**。

当前处理各电脑的**主屏幕**，每台客户端相对于服务端支持四向拼接与错位；暂不支持每台电脑的多显示器拓扑或登录前的系统后台服务。没有桌面画面传输，各电脑的屏幕都需要可见。键鼠一次只控制一台选中的客户端，不会向控制组广播相同输入。

## 使用方法（v0.9.1）

1. 主界面直接点击“启动服务端”或“启动客户端”。有键鼠的电脑启动服务端，需要接受控制的电脑启动客户端，无需先打开设置。
2. 两端启动后自动发现设备。客户端显示本次 6 位 PIN；设置窗口保留连接设置、手动 IP 和开机自启。
3. 服务端在“可用客户端”点击“申请控制”，客户端可“允许控制”或“拒绝”。同意后，服务端输入客户端显示的 PIN 完成连接。已获知 PIN 时，也可直接连接或将客户端拖入布局画布。
4. 客户端在“可用服务端”点击“申请加入”。服务端在申请列表中选择“同意并配对”，输入客户端 PIN；也可拒绝申请。申请不传输 PIN，每 2 秒重试，60 秒后过期。
5. 已连接的客户端在服务端显示“开始控制”和“解除控制”。前者将键鼠切到该客户端，后者断开该客户端，保留其他连接。客户端点击“离开服务端”立即释放输入并断开，然后生成新 PIN 重新等待，可申请加入其他服务端。
6. 也可将鼠标移到相接边缘进入客户端，反向返回。“返回本机”保留其他连接，“停止服务”关闭所有连接与发现。界面和画布标记当前控制的电脑，非当前设备隐藏光标，断线后恢复。
7. 连接期间可拖拽屏幕布局。调整时先安全返回服务端并释放输入，再同步新布局；文件传输期间需先完成或取消传输。PIN 和控制组不持久保存，不自动重新授予控制。

服务端是提供键鼠和管理控制组的应用角色。传输实现由服务端主动连接客户端的 TCP `24872`；客户端监听该端口。双方使用 UDP `24873` 和组播 `239.255.248.72` 发现设备。客户端启动后自动发布设备名称、系统和地址，不发布 PIN。

PIN 保留前导零，只接受 6 位数字，使用安全随机数生成。配对使用 PBKDF2-HMAC-SHA256（100000 次、双方随机数作盐）、双向挑战认证和 AES-256-GCM 会话；每个监听器每分钟最多接纳 5 次配对尝试。短 PIN 不能提供原 256 位随机凭据的抗离线猜测强度，请仅在可信局域网中配对。

访客网络隔离、防火墙、VPN 或组播限制可能阻止发现。同一 Wi-Fi 名称不保证设备互通；客户端须允许入站 TCP `24872`，双方须允许 UDP `24873`。macOS 如询问本地网络访问，请允许。

紧急返回：Windows 为 **Ctrl + Alt + Esc**，macOS 为 **Control + Option + Esc**。紧急返回会断开控制并释放模拟按键。

### 剪贴板与跨屏文件拖放

连接后新复制的纯文本或图片会自动同步到另一端，可在界面暂停。重新开启时不会补传暂停期间的内容。复制文件或文件夹时会传输原始字节、文件名和目录，完成后写入对端系统文件剪贴板，再到 Finder / Explorer 粘贴；图片文件不会转成 PNG 预览，文件夹不会变成路径文本。富文本格式不保留。各端请统一升级至 v0.9.0；控制会话协议升级到 7，发现协议仍为 1，旧版本无法配对。

从资源管理器或 Finder 拖起文件、文件夹，保持左键按下，移动到两屏相接的约 8 像素边缘。程序会取消原系统拖放，将内容传到对端暂存目录并校验，然后在对端启动系统复制拖放。等待就绪后继续拖到资源管理器 / Finder 的目标目录，松开鼠标。反向拖回本机也使用此流程。提前松开会取消等待；准备阶段最长等待 10 分钟。连接期间这条窄边缘用于接收系统拖放。

系统跨屏拖放会自动接收已配对电脑发来的文件。也可以把文件拖到应用传输区，或点击选择文件 / 文件夹；这种普通传输需接收方点击接受，大文件建议使用此方式。

传输始终复制，源文件不会删除。完成的接收副本保留在下载目录 `LAN Bridge/Received-<编号>`，以供系统拖放异步读取；确认目标复制完成后可手动清理。失败或取消的未完成临时目录会清理，不覆盖已有接收目录。

单次最多 100 GiB、10000 个条目；不支持符号链接、特殊文件、邮件虚拟附件和不兼容的 Windows 文件名。只传文件内容和目录结构，不保留 ACL、扩展属性、资源分叉或执行权限。目前 Linux 环境只验证了 Dart 逻辑与 Windows C++ 静态编译，不能据此认定 Explorer / Finder 实际拖放已经通过。

### 不同分辨率与切换（v0.7）

屏幕位置与移动增量按原生屏幕可用跨度归一化：4K 屏幕约 50% 高度进入 1080p 屏幕后仍位于约 50% 高度；反向返回同样换算。Windows 物理像素、macOS 原生坐标点、负坐标原点、竖屏和上下排列分别处理，不会直接把来源屏幕的像素坐标复制到目标屏幕。斜向移动使用与屏幕接缝的交点定位，避免大幅或合并移动导致返回位置偏移。

不同客户端切换时，先作废旧会话排队输入，并等待旧客户端确认释放按键，再交接焦点；连续鼠标移动可合并，但不会跨越按键、鼠标按钮或捕获状态的边界。返回本机后进入另一台客户端不再额外等待全局 350 毫秒。按住实体按键时，新电脑的键鼠接管会等待松开，防止将一个按键的按下与松开发给不同电脑。

这里的“相同位置”指屏幕中的相对位置，不是不同尺寸显示器上的相同厘米高度。每台电脑仍以主屏幕为单位；连接期间更改分辨率、缩放或主屏幕后请重新连接。自动化回环与模拟原生测试不能代替真实设备上的鼠标手感验收。

### 后台运行

关闭主窗口会隐藏界面，局域网发现、已建立的控制连接、剪贴板与文件传输继续运行。Windows 可点击系统托盘图标重新打开，右键菜单选择“退出”才会停止服务并结束进程；托盘创建失败时窗口会最小化到任务栏，保留重新打开的入口。Explorer 重启后会尝试恢复托盘图标。

macOS 关闭红色窗口按钮或使用 Command + W 会隐藏窗口，可从菜单栏图标或 Dock 重新打开。“退出”菜单或 Command + Q 会先停止服务、释放模拟输入并清理会话，再退出应用。应用在后台保留系统活动声明以避免 App Nap 延迟输入心跳，同时允许系统按正常规则休眠。

关闭某一块被控屏幕右上角的 × 仍会放弃对该客户端的控制，与关闭应用主窗口是两个不同操作。后台运行指当前用户登录期间的应用运行，不是登录前的系统服务。

托盘 / 菜单栏会实时显示连接信号格，以及当前键鼠控制位置。macOS 用“本 / 远”、Windows 用“L / R”标记当前控制的电脑是否为本机；菜单和悬停提示会进一步显示远端名称或“本机正被远端控制”。信号格根据应用连接的往返延迟与延迟抖动更新，详情以毫秒显示，不代表 Wi-Fi 射频强度。未连接或尚未获得测量结果时显示空格；旧版对端未回应测量时不会伪造信号数据。

### 自由排列与开机自启

屏幕预览显示服务端与当前选中客户端的主屏幕，两块区域以等大逻辑区域表示。多机模式中所有已加入客户端同时显示，可直接拖动调整排列并在线同步。拖动过程中可自由移动，靠近主机边缘或角点时出现吸附预览，松开应用。远离相接边缘松开会恢复原位置，以保持可穿越通道。拖动被控屏幕会吸附到主机四边，可沿相接边缘错位（最多 90%，至少保留 10% 通道）。画布通过边缘和角点吸附调整；角点保留至少 10% 的重叠作为穿越通道。鼠标和文件拖放都只从两块屏幕相接的区域穿越；分辨率或 DPI 不同仍按比例映射。显示器之间需要有相接边缘，不支持隔空跨越。

“开机自启”在当前用户登录 Windows / macOS 后打开应用；不会自动开启监听或自动配对。角色和布局保存在用户应用支持目录的 `settings.json`，密钥不保存。

Windows 使用当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的 `LANBridge` 启动项。macOS 使用 `~/Library/LaunchAgents/com.lanbridge.login.plist`。开关关闭时删除对应项。请先把应用安装到固定目录再开启，移动应用后需要关闭并重新开启。卸载前先关闭自启；登录前运行的 Windows Service / macOS Daemon 不在本版范围内。

### macOS 权限

在“系统设置 → 隐私与安全性”中，为实际运行的 `lan_bridge.app` 授予**辅助功能**和**输入监控**权限。应用提供权限请求入口，系统是否立即显示弹窗由 macOS 决定。授权后如果系统要求，退出并重新启动客户端；移动应用位置或更换构建后可能需要重新授权。系统如询问本地网络访问，请允许局域网通信。该应用需要系统范围的事件捕获与注入，因此 macOS 构建未启用 App Sandbox；面向直接分发，不是 Mac App Store 沙盒应用。

### 输入边界

按键使用 USB HID 物理键位映射，字符与输入法由被控电脑的键盘布局决定。Windows 的 Windows 键与 macOS 的 Command 键按对应物理修饰键映射，不会自动将所有 Ctrl 快捷键改写为 Command 快捷键。少见专用键、媒体键、系统保留快捷键、输入法组合与触控板细微滚动需要按设备验证。

普通用户进程无法可靠控制 Windows UAC 安全桌面或更高权限窗口；`Ctrl + Alt + Delete` 等安全序列无法模拟。macOS 的安全输入状态、登录界面、锁屏或系统权限限制也可能阻止捕获。屏幕缩放和不同设备鼠标加速可能影响跨系统手感。改变分辨率、主屏幕或显示缩放后请重新连接。

## 本地开发与构建

安装 Flutter 3.47.7（Dart 3.13.5），执行 `flutter doctor`。Windows 10/11 x64 需要 Visual Studio 2022 的“使用 C++ 的桌面开发”工作负载和 Windows SDK；macOS 12 或更新系统需要 Xcode、命令行工具及 CocoaPods。Flutter 桌面原生构建需要对应操作系统：Linux 可以运行 Dart/Flutter 单元测试，但不能直接生成这两个系统的正式客户端。

```bash
flutter pub get
flutter analyze
flutter test
```

Windows（PowerShell）：

```powershell
flutter run -d windows
./scripts/build-windows.ps1
```

需要额外安装 Inno Setup 6。输出 `dist/lan-bridge-windows-x64-0.9.1-setup-unsigned.exe` 安装器、便携 ZIP 及 SHA-256 文件。安装器按当前用户安装，并包含 VC++ 运行库。便携 ZIP 解压后启动 `lan_bridge.exe`；必须保留同目录的所有 DLL 和 `data` 文件夹，不可只复制 EXE。视目标系统情况，可能还需安装 Microsoft Visual C++ x64 Redistributable。

macOS：

```bash
flutter run -d macos
bash scripts/build-macos.sh
```

输出 `dist/lan-bridge-macos-0.9.1-unsigned.dmg`、便携 ZIP 及 SHA-256 文件。打开 DMG 后将 LAN Bridge.app 拖入 Applications；使用 ZIP 时，解压后将 `lan_bridge.app` 移到“应用程序”。该包未经 Developer ID 发行签名与 Apple 公证；Xcode 可能生成用于本地运行的临时签名。macOS 可能阻止首次打开，应先确认来源和校验值，再按系统“隐私与安全性”中的提示处理。发行时应替换为正式签名与公证流程。

## 自动构建与发布

将本目录作为 Git 仓库根目录上传到自己的 GitHub 仓库后：

- `Build and publish desktop installers` 可在 Actions 页面手动运行，验证代码并在 Windows/macOS 原生 runner 上生成 EXE 安装器、DMG、便携 ZIP 和 SHA-256 文件。
- 推送 `v0.9.1` 等与 `pubspec.yaml` 一致的版本标签时，执行同样的验证与构建；两端构建和安装包检查都成功后，自动创建 GitHub **预发布版本**并上传全部产物。
- 手动运行仅生成 Actions 构建产物，不创建 Release。工作流固定 Flutter 3.47.7，使用已提交的锁文件。仓库需允许 Actions 运行，发布 job 使用 `contents: write` 权限。
- 发布说明放在 `docs/releases/<标签>.md`。安装包未经发行签名；Linux 测试、安装器静默安装/卸载、DMG 挂载与校验均不能代替双机原生输入验收。

正式公开发行需要自行配置 Windows Authenticode 签名、macOS Developer ID Application 签名与 Apple 公证。在 macOS 上先为应用及嵌入组件正确签名并开启适用的 Hardened Runtime，使用 `xcrun notarytool submit … --wait` 提交公证，再用 `xcrun stapler staple …` 附加票据，最后重新打包并计算校验值。证书、签名密码和公证凭据应存入 CI 的 Secrets，不能提交到仓库。当前脚本不包含发行凭据，也不会声称包已经签名。

## 结构与验证

```text
lib/                       Flutter 界面、连接状态与跨屏逻辑
lib/core/secure_transport.dart  配对认证和加密 TCP 传输
packages/lan_input/         Dart 通道、Windows C++、macOS Swift 原生实现
windows/、macos/            Flutter 桌面运行器
test/                      协议、边界与状态相关自动化测试
scripts/                   本地双平台打包
.github/workflows/          CI 与预发布构建
docs/manual-test.md         双机验收清单
```

自动化测试不能证明系统权限、驱动、事件钩子和真实屏幕跨越已经可用。发布前必须在实际 Windows 与 macOS 电脑上完成 [双机验收](docs/manual-test.md)，至少覆盖 Windows → macOS 和 macOS → Windows 两个方向。尚未执行的检查应记录为“待验证”，不能记作通过。

本次环境的实际检查结果见 [验证记录](docs/verification.md)。
