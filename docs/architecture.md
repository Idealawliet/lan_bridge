# 实现与协议

## 职责

Flutter/Dart 实现中文桌面界面、连接生命周期、屏幕坐标换算及加密 TCP 通道。`lan_input` 通过 MethodChannel / EventChannel 连接 Windows C++ 和 macOS Swift；Flutter 窗口不需要保持焦点。

网络角色独立于键鼠角色：客户端主动连接，服务端显式开启 TCP 24872 监听；键鼠主机可以作为任意网络角色。连接前双方都检查原生输入支持与权限，连接后交换角色、协议版本、主屏幕尺寸、四向布局和错位参数。只有主机可发送控制消息，被控端只有在收到 `enter` 后才接受输入。目标电脑的物理输入不会被反向转发。

主机上的鼠标到达选定边缘时，原生层检查是否仍有物理按键或鼠标按钮按下。空闲后开启远程捕获：Windows 用低级输入钩子、中心锚点和带标记的 SendInput；macOS 用 CGEventTap、光标与鼠标解耦和带标记的 CGEvent。远程键盘使用 USB HID 键位，不传输 Unicode 文本；接收端的布局和输入法决定最终字符。

远程指针由主机维护。进入时按相接边缘的相对位置映射，之后按原生鼠标增量移动；返回时释放被控端按键，将本机指针放在边缘内侧，添加短暂冷却以免来回抖动。上下左右四向对称，错位后仅相接区域可穿越。每台电脑的多显示器拓扑不在本版协议范围内。

## 认证与传输

每次监听产生 32 字节安全随机密钥，显示为 43 字符 Base64URL 字符串。该密钥是持有者凭证，需通过可信方式传给主机；不会保存到磁盘。不是可自选的短密码。

1. 客户端和服务端分别产生 32 字节随机挑战。
2. 双方对带协议标识、双方挑战及角色标签的内容计算 HMAC-SHA256，完成双向认证与确认。
3. HKDF-SHA256 使用配对密钥和会话挑战派生两个独立方向的 256 位密钥。
4. 数据使用 AES-256-GCM；12 字节 nonce 由递增序号构造，序号同时进入认证附加数据。接收方只接受精确的下一序号，拒绝篡改与重放。

TCP 帧为有大小限制的换行 JSON。最大线帧 16 KiB，明文消息上限 10 KiB；握手和写入均有超时，最多同时保留四个未认证握手、一个认证连接。输入处理按序执行；出现积压会断开，避免持续执行过期输入。此协议依赖配对密钥与新挑战，不提供前向保密，也尚未接受独立安全审计。

## 恢复与局限

Flutter 每 500 ms 驱动原生心跳并发送会话心跳，约 3 秒无有效消息会断开。Windows 独立消息循环线程和 macOS 独立定时队列在原生心跳缺失约 2.5 秒时恢复输入并释放模拟按键。时限受系统调度影响。

Ctrl+Alt+Esc（macOS 为 Control+Option+Esc）在原生层先恢复本机，再通知 Dart 断开。两端都支持紧急停止。原生事件带标记以避免注入回环，队列有上限并合并连续鼠标移动。断开、关闭窗口和销毁插件均尝试释放输入。

系统安全桌面、锁屏、macOS 安全输入、硬件专用键、特殊驱动及不同 DPI/鼠标加速仍需实机验证。辅助功能权限不等于系统管理员权限；应用不会自行提权。


## v0.2 分享通道

应用 hello 协议升级到 2，加密传输协议保持不变。剪贴板与文件帧复用已认证的双向通道，独立状态机负责分块确认。剪贴板按系统版本号轮询，以内容摘要抑制回传，并限制 8 MiB。文件流每块 6144 字节，接收端验证相对路径、父目录、大小、偏移及 SHA-256；完成后将私有临时目录改名为独立接收目录。

跨屏系统拖放分成边缘捕获、取消原会话、传输及校验、目标系统启动复制拖放、继续鼠标操作五步。反向拖回主机时恢复物理鼠标控制。网络帧到达时刷新存活时间，避免磁盘处理排队造成误断开；取消时先恢复原生输入再取消传输。原生系统拖放仍需在目标系统实际验证。


## v0.3 排列、网络角色与登录启动

应用 hello 协议为 3，携带 `side`（left/right/top/bottom）与 `offset`（-0.9 到 0.9）。主机布局是权威值。两块屏幕在归一化逻辑空间排列；进入时切向位置减去 offset，返回时加上 offset，只有映射落在 [0,1] 内才能跨屏。原生文件边缘按双方相接区裁剪，事件同时包含 x/y，文件帧的 y 字段在协议 3 表示目标边缘上的归一化切向位置。

`ConnectionMode` 决定监听或主动连接；`BridgeRole` 决定输入来源，两者独立。握手依然要求互补键鼠角色。`DesktopSettings` 串行保存非敏感偏好；`LoginStartup` 使用 Windows 当前用户 Run 项或 macOS LaunchAgent，命令参数不经 shell 拼接。自启只打开应用，不保存配对密钥或自动建立控制会话。


## v0.4 多客户端控制组

`LanDiscovery` 使用 IPv4 组播 `239.255.248.72:24873`，在每个可用接口加入组并发送发现查询 / 客户端公告。周期 2 秒，过期 7 秒。公告上限 1200 字节、列表上限 256 项，按临时实例 ID 去重。查询回复限频；未知或畸形数据忽略。接收端只使用 UDP 源 IP，公告不能指定另一个控制地址。发现元数据不可信，也不携带配对密钥。

`LanWorkspace` 为每台已选择客户端创建独立 `BridgeController` / `SecurePeer`，最多 16 个；原单客户端监听器仍限制一名控制者，不能让不同服务端同时控制一个客户端。多机管理服务端主动连接可发现客户端的监听端，配对仍要求其随机 256 位密钥。原双机手动连接路径不变。

`InputRouter` 只创建一个系统钩子，按引用计数管理原生捕获。每个会话使用 `RoutedInput`；普通事件、输入注入、鼠标定位和文件边缘仅转发给当前焦点会话，紧急恢复事件分发给全部会话。每个会话保持网络心跳，移除一个不会停止其他会话的捕获。切换先恢复旧会话的本地控制、释放模拟键，再更新焦点和文件边缘；切换途中暂停普通事件路由。

本机边缘匹配可自动切换焦点；远端到另一个远端必须经本机。重叠边缘优先当前选择，再按加入顺序匹配。后台会话剪贴板关闭，焦点变化会重建基线；文件传输中禁止切换。停止服务等待进行中的加入操作结束并清理所有会话。客户端掉线后保留控制组中的离线项，用户可移除；重新公开客户端会生成新的密钥，不存储长期信任或自动重连凭据。


## v0.6 窗口与服务生命周期

原生窗口的关闭操作只隐藏窗口，保持 Flutter engine 与 Dart 定时器运行。Windows 在插件处理前拦截 WM_CLOSE，托盘菜单负责重开与明确退出；macOS NSWindowDelegate 返回 false 并 orderOut，菜单栏入口可恢复同一个窗口，最后窗口关闭不终止应用。

明确退出通过 `lan_bridge/lifecycle.prepareQuit` 请求 Dart 停止全部会话并恢复输入，成功后才销毁引擎 / 结束应用。重复退出共享同一个清理任务；清理失败不退出，可重试。macOS 持有允许系统休眠的用户活动声明，避免 App Nap 对输入心跳的后台节流。窗口隐藏不会触发 widget dispose 或退出清理。


## v0.7 输入流与分辨率

应用协议为 5。`leave(id)` 后目标端先调用原生 releaseAll，再回复 `left(id)`，来源端在确认后才交接焦点；等待上限 1 秒，旧端异常则断开旧会话，避免阻挡健康客户端。

`InputEventQueue` 在路由层及连接控制器层合并同一会话的相邻移动，保留最新绝对坐标并累加相对增量。按键、按钮、滚轮、会话代次及捕获模式均作为合并边界。焦点交接先暂停旧控制器、清空待执行输入并等待当前处理完成，之后返回本机并等待释放确认。修复了旧控制器已收到但未处理的输入在焦点切换后重新进入旧屏幕的问题。原生 Windows/macOS 移动事件增加 captured 标记，本地移动与已捕获相对移动不能混合或误解释。

目标相对增量为 `dx * (target.width - 1) / (source.width - 1)`，y 同理。穿越位置按归一化边缘坐标与 offset 映射；斜向返回先计算线段和相接边缘的交点。系统剪贴板收帧使用独立的顺序任务链，避免 OS 写入阻塞键盘松开、离开和心跳控制帧。
