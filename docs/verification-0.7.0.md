# v0.7.0 输入切换验证

环境：2026-10-25，Linux x64，Flutter 3.47.7 / Dart 3.13.5。

已完成 91 项完整自动化测试，`flutter analyze --no-pub` 无问题。Windows 插件以 MinGW GCC 14、C++20、当前 Flutter 头文件及 `-Wall -Wextra -Werror` 通过静态编译检查。

## 修复与证据

- 已先复现：跨屏接管尚未完成时切换焦点，旧端可能重新激活并收到旧按键。修复为暂停旧控制器、作废其排队事件、等待当前事件收尾，再返回本机和交接焦点。
- 已先复现：返回本机后立即从另一条边缘进入另一台客户端，被全局 350 毫秒等待挡住。移除全局等待，保留同一会话正常返回时的防抖，新焦点重置旧冷却。
- 已先复现：目标系统剪贴板写入被挂起时，键盘松开也被阻塞。剪贴板与输入控制分开顺序处理，回归测试确认写入未完成时已可注入松开事件。
- 高频移动采用相邻样本合并，保留位移总和及最新绝对位置；键盘、鼠标按钮、滚轮、捕获状态、会话上下文不跨界合并。测试 5,000 个移动样本加 100 个后续移动，待处理队列峰值不超过 4，合并 5,098 个样本；按下和松开顺序不变。另以 6,000 个移动样本验证路由不溢出且最终按钮松开不丢失。
- 原生移动增加捕获模式标记，接管前的本地样本不会在接管后被误作相对位移。回归覆盖大幅本地积压样本不造成目标位置跳动。
- 协议 5 增加目标释放确认，旧端释放模拟输入后才交接焦点，避免只发送离开消息却没有确认旧端处理完成。

## 分辨率覆盖

真实加密回环连接覆盖 5 组不同分辨率 / 坐标原点 × 4 个方向的进入和返回：4K→1080p、1080p→4K、8K→1080p、1512×982 的 Retina 逻辑坐标→2560×1440、1080×1920 竖屏→3440×1440。分别验证相对边缘位置和返回位置。

纯几何矩阵使用 8 种屏幕、任意两两组合、四方向、5 种错位、21 个边缘采样位置，共 26,880 次往返检查；另验证相对增量换算可逆。独立测试 4K→1080p 移动增量比例及斜向返回使用接缝交点，而不是越界终点。

## 多机压力场景

三条独立 AES-GCM 回环 TCP 会话共切换 60 次，产生 90,000 个鼠标样本，每轮带键盘和鼠标按钮按下 / 松开；核对总位移、输入顺序、旧端已返回及所有连接存活。底层捕获只启动一次。

本次运行耗时 7,834 毫秒。测试观测到的切换至目标进入状态：中位数 12.158 毫秒，P95 13.977 毫秒，最大 24.615 毫秒。**这些是同机回环与模拟原生层的观测值，包含测试状态轮询，不是实体键鼠端到端延迟，也不构成 Wi-Fi 或系统延迟保证。**

## 尚需实机验证

没有在本环境执行 Windows MSVC / macOS Xcode 完整构建、系统权限测试、实体鼠标回报率和驱动手感、多台机器的 Wi-Fi 时延或系统级跨屏文件拖放。macOS 的捕获模式修改尚未原生编译。各电脑仍按主屏幕映射；更改分辨率 / 缩放 / 主屏后需重新连接。真实设备验收按 manual-test.md 执行。
